# TOOL NEXUS

ローカルで動かしている複数の Streamlit ツール（および Flask / FastAPI / Python スクリプト / 実行ファイル）を、
**登録・起動・停止・状態確認するためのローカル専用ランチャー**です。

自作ツールが増えるほど「どこに何があるか」「今どれが起動しているか」「どのポートを使ったか」が分からなくなります。
TOOL NEXUS はその入口を1つにまとめます。

姉妹ツール [LIST NEXUS](https://github.com/velaciela-ringWing2007/list-nexus)（SharePoint Listリンク管理）と、
画面の骨格・配色・実装方針を共有しています。設計の詳細は [SPEC.md](SPEC.md) にあります。

## 主な機能

* ツールの登録・編集・削除（名前、作業ディレクトリ、起動コマンド、ポート、ログ出力先など）
* **ファイルから登録**：起動する `.py` / 実行ファイルを選ぶと、作業ディレクトリ・venv / uv・種別・起動コマンドを推測して入力
* 起動 / 停止 / **まとめて起動**（起動中のものは飛ばす）
* 状態表示（起動中 / 起動中… / 起動できていない可能性 / 停止）を画面を開いている間だけ自動更新
* **ポートの自動割当**（保存時に割り当ててDBに残すので、ブックマークが壊れない）
* **起動中のStreamlitの検出**と、値を入れた状態での登録
* 「開く」で `http://127.0.0.1:<port>` を新しいタブで開く、ログの末尾を画面で確認
* 設定画面（並べ替え・まとめて削除、動作設定、JSONバックアップと復元）
* Windows と Linux（Ubuntu）の両方で動作
* サイバーパンク風ダークテーマ

## 必要環境

* Windows 11 または Linux（Ubuntu 24.04 で確認）
* Python 3.12以上
* ブラウザ
* Linux でファイル選択を使う場合は `zenity` か `kdialog`（例: `sudo apt install zenity`）
* 依存パッケージは `streamlit` と `pytest` のみ（`requirements.txt`）

`psutil` は使いません。プロセス情報は Windows では PowerShell（`Get-CimInstance` / `Get-NetTCPConnection`）、
Linux では `/proc` から取得します。`streamlit` が連れてくる依存パッケージの内訳は
[LIST NEXUS の README](https://github.com/velaciela-ringWing2007/list-nexus#依存パッケージ) と同じです。

## セットアップ

**Windows**：`setup.bat` をダブルクリックします。仮想環境の作成・依存パッケージのインストール・DB初期化まで行います。

**Linux**：

```bash
./setup.sh
```

手動で行う場合：

```bash
python -m venv .venv
.venv\Scripts\activate          # Linux は source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

## 起動方法

**Windows**：`start-tool-nexus.bat` をダブルクリックします。**Linux**：`./start-tool-nexus.sh`

* `http://127.0.0.1:8499` でブラウザが開きます
* 待ち受けは `127.0.0.1` のみです（外部ネットワークからは接続できません）
* TOOL NEXUS 自身は **8499** で動きます。管理するツールに自動で割り当てる範囲（既定 8500〜8999）の外に置いています
* TOOL NEXUS を閉じても、TOOL NEXUS から起動したツールは動き続けます（意図した挙動）

## 使い方

### ツールを登録する

右上の「追加」から登録します。「**ファイルから入力**」で起動する `app.py` などを選ぶと、次を推測して入力します。
推測は入力欄に入れるだけなので、フォーム下部の「**実行されるコマンド**」を確認してから登録してください。

| 見つかったもの | 使う Python |
| --- | --- |
| `pyvenv.cfg` のある venv（`.venv` / `venv` / `env` を優先。名前は問わない） | その venv の python |
| `uv.lock` だけがある | `uv run python` |
| どちらも無い | Windows は `py`、Linux は `python3` |

| ファイルの中身 | 種別 | 起動コマンド |
| --- | --- | --- |
| `import streamlit` | Streamlit | `<python> -m streamlit run app.py` |
| `Flask(` | Web | `<python> -m flask --app app.py run --host 127.0.0.1 --port {port}` |
| `FastAPI(` | Web | `<python> -m uvicorn app:app --host 127.0.0.1 --port {port}` |
| それ以外の `.py` | Python | `<python> script.py` |
| 実行ファイル | EXE | そのまま |

### 種別と `{port}`

| 種別 | 起動時の動作 | 死活監視の既定 |
| --- | --- | --- |
| Streamlit | `--server.port` / `--server.address 127.0.0.1` / `--server.headless true` を自動付与（コマンドに書いてあれば付けない） | HTTP（`/_stcore/health`） |
| Web | コマンド中の `{port}` を登録済みのポートに置き換える | HTTP（`/` に応答すれば生存） |
| Python / EXE | `{port}` があれば置き換える | プロセス |

ポートを空欄で保存すると、**Streamlit か、コマンドに `{port}` を含む場合だけ**空きポートを自動で割り当てます。
割り当てたポートで実際に待ち受けることが保証できない場合（`{port}` の無い Web など）は、実際のポートを入力してください。

### 死活監視

| モード | 方法 |
| --- | --- |
| HTTP | `http://127.0.0.1:<port>` に応答するか（Streamlit は `/_stcore/health`） |
| プロセス | 起動したプロセスが生きているか（PIDと起動時刻で照合） |
| 監視しない | 監視しない |

* 監視は**画面を開いている間だけ**行います（常駐しません）。既定の間隔は60秒で、設定で変えられます
* 起動直後の30秒は「起動中…」、それを過ぎても応答しなければ「起動できていない可能性があります」と表示します。
  ログのボタンから原因を確認できます

### 停止

* 停止の前に、記録したPIDの**起動時刻を照合**します。ツールが落ちた後にOSがPIDを再利用していると、
  無関係なプロセスを止めてしまうためです。照合が取れない場合は止めません
* TOOL NEXUS の外で起動したツールなどは、**ポートで待ち受けているプロセスを探し、PIDとコマンドラインを見せて確認を取ってから**停止します
* Windows は子プロセスごと強制終了（`taskkill /T /F`）、Linux はまず SIGTERM、残っていれば SIGKILL です

## 画面構成

```text
┌────────────────────────────────────────────────────────┐
│ TOOL NEXUS  [すべて][Streamlit][Web][Python][EXE]    [⚙] │ ← 上部バー（全幅）
├───────────┬────────────────────────────────────────────┤
│ 状態       │ 検索                        [▶][◎][＋追加] │
│ ○すべて    │ 起動中 1 / 3   最終確認 21:00   [再チェック]  │
│ ○起動中    │ ● 在庫チェッカー   8502 [開く] [停止][ログ][編集]│
│ ○停止中    │ ○ 集計ツール       8503 [開く] [起動][ログ][編集]│
│ ○要確認    │                                              │
└───────────┴────────────────────────────────────────────┘
```

* ▶ まとめて起動、◎ 起動中のStreamlitを検出、⚙ 設定
* 状態の丸：シアン＝起動中、黄＝起動中…、赤＝起動できていない可能性、グレー＝停止
* 削除は誤操作を避けるため、編集画面の奥（または設定の「ツールの管理」）にあります

設定画面：

* **ツールの管理** … 表示順・まとめて起動の一括編集、まとめて削除
* **検出** … 起動中のStreamlitの一覧と登録
* **動作設定** … 監視の間隔、タイムアウト、自動割当の範囲、予約済みポート、ログの既定フォルダ
* **データ** … DBの場所、JSONバックアップ、復元

## 予約済みポート

自動割当で使わないポートです。既定は **8501**（LIST NEXUS が使用）。
TOOL NEXUS 自身の 8499 は設定に関わらず常に除外します（停止中に他のツールへ割り当てると、次回 TOOL NEXUS が起動できなくなるため）。
手動で固定しているポートがあれば、設定の「予約済みポート」に追加してください。

## データ保存場所

* データベース：`data/tool_nexus.sqlite3`（Git管理外）
* ツールのログ：既定では各ツールの作業ディレクトリの `tool-nexus.log`（設定で既定フォルダを変更可能）

起動中かどうかはDBに保存しません（保存した瞬間から、クラッシュしても「起動中」のまま嘘になるため）。
DBには設定と起動の記録だけを持ち、状態は毎回確認します。

## JSONバックアップ

設定画面の「データ」から保存・復元できます。含めるのは**ツールの設定と動作設定だけ**で、
起動の記録（PIDなど）や内部IDは含みません。形式は [SPEC.md の 7.3](SPEC.md) を参照してください。

| 復元の方法 | 動作 |
| --- | --- |
| 追加（既定） | 既存を残して追加。名前と作業ディレクトリが同じもの、ポートが衝突するものは飛ばす |
| 置き換え | 既存のツールをすべて削除してから復元（確認のチェックが必要） |

別PCのバックアップも取り込めます（作業ディレクトリの存在は復元時には確認せず、起動時に確認します）。

## テスト実行方法

```bash
python -m pytest
```

* 実プロセスを起動する結合テスト（`tests/test_integration.py`）も含みます。外す場合は `python -m pytest -m "not integration"`
* OSに依存する部分は、Windows用・Linux用ともに**どちらのOSでも**テストできます（Linux の `/proc` は疑似ディレクトリで検証）
* GitHub Actions で Windows と Ubuntu の両方でテストしています

## 既知の制約

* 画面を開いている間しか監視しません
* プロセスモードでは「固まっているが生きている」状態を検出できません
* 管理できるのはこのPC上のプロセスのみです
* Windows の停止は強制終了（`taskkill /F`）で、ツール側の終了処理は走りません
* TOOL NEXUS を**プロセスツリーごと**終了させた場合（`taskkill /T` など）は、起動したツールも止まります
* Windows では、起動コマンドに `--name="a b"` のようにトークン途中のクォートで空白を含める書き方はできません。
  `--name "a b"` と分けて書いてください
* `.bat` / `.cmd` は登録できません（cmd.exe 経由の引数エスケープに問題があるため）
* ファイル選択のダイアログは TOOL NEXUS を動かしているPCの画面に出ます（同じPCのブラウザから使う前提）
* 起動方式の推測はファイルの中身の簡単な判定で、外れることがあります。登録前にコマンドを確認してください
* macOS は未対応です（`/proc` が無いため）

## 実装上の判断メモ

実機で確認して決めたことです。詳細は [SPEC.md](SPEC.md) にあります。

* **Windows の起動フラグに `DETACHED_PROCESS` を使わない**。`CREATE_NO_WINDOW` と併用すると後者が無視され、
  venv の python.exe（リダイレクタ）の子がコンソールウィンドウを出し、それを閉じるとツールが落ちます
* **`Popen.pid` は親で、ポートを持つのは子**（Windows の venv）。停止は子ごと行い、検出はポートを持つ子から親へたどります
* **起動時刻の表記は PowerShell の取得方法で3通りに揺れる**（CIM datetime / `/Date(ms)/` / ISO）。すべて秒精度のISO 8601に正規化して比較します
* **実行ファイルのパスはシンボリックリンクをたどらない**。Linux の venv の python はシステムの python へのリンクで、たどると venv の外になります
* **Linux では終了した子がゾンビとして残る**。ゾンビも起動時刻が同じで「生きている」と誤判定されるため、回収し、状態 `Z` は存在しない扱いにします
* **一覧はフラグメントで3秒ごとに描き直し、ヘルスチェックは必要なときだけ行う**。更新間隔をその場で切り替える方式は、前回の描画が消えずに残りました
* 1行のウィジェットは3個（起動/停止・ログ・編集）に抑え、「開く」は素のアンカーで描いています（LIST NEXUS の実測に基づく）

## トラブルシューティング

**`start-tool-nexus.bat` が「Python仮想環境がありません」と表示する**
`setup.bat`（Linux は `./setup.sh`）を先に実行してください。

**ポート8499が使用中で TOOL NEXUS が起動しない**
既に TOOL NEXUS が起動しています。既存のウィンドウを閉じてから起動し直してください。

**「起動できていない可能性があります」と表示される**
ログのボタンでツールの出力を確認してください。コマンドの誤り、venv にパッケージが入っていない、
ポートが他のプロセスに使われている、などが多い原因です。

**「対象プロセスを特定できませんでした」と表示される**
ツールが既に終了しているか、TOOL NEXUS の外で起動されています。ポートを登録しているツールなら、
ポートで待ち受けているプロセスを探して停止の確認を出します。

**Linux で「ファイル選択には zenity または kdialog が必要です」と表示される**
`sudo apt install zenity` を実行してください。パスを手で入力して登録することもできます。

**データを初期状態に戻したい**
TOOL NEXUS を終了してから `data/tool_nexus.sqlite3`（および `-wal` / `-shm`）を削除してください。
削除前に設定画面の「データ」でバックアップを保存しておくことを推奨します。

**画面表示が崩れる / 古い状態が残る**
ブラウザで `Ctrl + F5`（キャッシュを無視した再読み込み）を実行してください。
